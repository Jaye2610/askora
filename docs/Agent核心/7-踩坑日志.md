# 7 · 踩坑日志

> 这份日志整理了本项目开发与部署过程中真实遇到、并有对应修复的"坑"，按主题分组。每条都标注了**现象 → 根因 → 修复/规避**，并尽量对应到真实 Commit。它既是你排查时的速查表，也是你向面试官证明"我真的经历过生产问题"的素材。多数可直接对照本仓库 git 历史验证。

---

## 7.1 构建 / 环境类

### 坑 1 · 干净环境 `mvnw test` 直接崩溃
- **现象**：`mvn test` 报 `error: 找不到 symbol` 或 fork JVM 崩溃
- **根因**：surefire 配了 `@{argLine}`，但项目没接 jacoco，`argLine` 属性不存在，fork 出的测试 JVM 收到**字面量 `@{argLine}`** 直接崩
- **修复**：在根 `pom.xml` 定义 `<argLine/>` 空默认值（提交 `43c5504`）
- **教训**：占位符属性必须有默认值兜底，别让工具链耦合到不存在的插件

### 坑 2 · PostgreSQL 必须用 pgvector 镜像
- **现象**：后端启动失败，报 `relation "t_knowledge_vector" does not exist` 或 `type "vector" does not exist`
- **根因**：向量检索用 pgvector 扩展，普通 `postgres:16` 没有该扩展，建表/查询都会失败
- **修复**：用 `pgvector/pgvector:pg16` 镜像，并**手动执行** `schema_pg.sql`（项目不用 Flyway 自动建表）
- **教训**：看部署文档别用默认 postgres 镜像（`docs/DEPLOYMENT.md` 里特意标注了这条）

### 坑 3 · 编译失败：refactor 后残留旧包声明
- **现象**：`infra-ai` 模块 `找不到符号 HttpResponseHelper`
- **根因**：包结构迁移到 `io.github.jaye.ai.askora` 时，`HttpResponseHelper.java` 的 `package` 声明没跟着改（仍 `io.github.jaye.infra.http`），与 4 个消费方 import 的 `io.github.jaye.ai.askora.infra.http` 不一致
- **修复**：把该文件 package 声明对齐
- **教训**：大范围包重命名后要全量编译自检，单文件漏改会在编译期才暴露

## 7.2 检索类

### 坑 4 · 检索去重与合并的四个缺陷
- **现象**：多通道召回后块重复、合并错乱（提交 `6368bca`）
- **根因**：去重键不统一（有的块无 id）、合并逻辑未按序
- **修复**：`RetrievedChunkKey` 统一去重键——有 id 用 id，否则 **SHA-256 文本哈希**，保证联网等无 id 块也能去重

### 坑 5 · 向量分数脏值污染排序
- **现象**：个别 chunk score 为 null/NaN/NaN 时排名错乱
- **根因**：下游比较器遇到脏分不确定行为
- **修复**：`RetrievedChunk.BY_SCORE_DESC` 把 null/NaN/±∞ 归一到 `-inf` 沉底
- **教训**：跨通道、跨供应商的分数不能假设永远合法

### 坑 6 · RRF k 值过大平滑头部
- **现象**：融合后头部候选没有区分度，弱通道靠名次抢前排
- **根因**：候选池通常只有 20~40 条，`rrf-k=60` 过度平滑
- **修复**：调到 `rrf-k=20`，配合"检索归因"日志校准
- **教训**：超参要么有数据支撑要么有观测闭环，别拍脑袋

### 坑 7 · 图谱证据"纯成本"：进候选多、存活少
- **现象**：图谱通道塞了一堆候选进 Rerank，却几乎不存活
- **根因**：长图谱证据可排性差，或权重过高
- **修复/建议**：`RerankPostProcessor` 加"图谱证据存活率"归因日志（`graphOut/graphIn`），据此下调 `fusion.channel-weights.graph` 或优化证据
- **教训**：通道好不好不能只看召回，要看**精排后的存活率**

### 坑 8 · 向量通道拆成"定向+全局"两条会自我加权
- **现象**：同一份证据在 RRF 里被算了两次，权重虚高
- **根因**：早期把定向、全局拆成两个并列通道
- **修复**：合并为单一 `VectorSearchChannel`，内部按作用域分流（`1c40cdd`）

### 坑 9 · topK 多义性导致配置混乱
- **现象**：`topK` 一词同时指"召回深度""候选池大小""最终条数"，配错谁也说不清
- **根因**：没有区分漏斗各段的语义
- **修复**：按第一性原理拆分三段预算 `recall-budget / rerank-candidate-limit / default-top-k`，启动校验单调收窄（`9a65b76`）

## 7.3 意图 / 问题理解类

### 坑 10 · 空意图树也调 LLM 分类
- **现象**：没有配置任何意图节点时仍发起 LLM 调用，浪费成本
- **修复**：空意图树短路跳过（`2935124`）

### 坑 11 · Redis 缓存 JSON 反序列化失败
- **现象**：意图缓存反序列化抛异常导致问答失败
- **根因**：缓存对象结构变更后旧 JSON 无法反序列化
- **修复**：容错处理（`8128b8a`）
- **教训**：缓存 schema 有版本/兼容问题，取到坏数据要能优雅降级

### 坑 12 · 意图归属选错了提示词
- **现象**：按"预测意图"选 prompt 模板，但实际检索命中的证据却属于另一个意图
- **根因**：用分类预测而非真实召回归属
- **修复**：按**真实召回归属**选择意图提示词（`9d80d7a`）

## 7.4 模型 / 熔断类

### 坑 13 · 首包探测中断导致半开名额永久占用
- **现象**：模型"卡在半开"，后续请求全被拒
- **根因**：首包探测在流式中途中断，探测请求持有的半开名额没释放
- **修复**：由持有者 `releaseHalfOpenPermit` 释放（`9509b02`）
- **教训**：HALF_OPEN 的互斥名额必须有可靠的释放路径，否则模型永久冻结

### 坑 14 · 空白 LLM 响应被当成成功
- **现象**：模型返回空内容，仍被记成成功、不降级
- **根因**：没校验响应是否空白
- **修复**：拒绝空白响应并触发降级到下一候选（`3bfb3d7`）

### 坑 15 · 未开启思考时仍传思考开关
- **现象**：对不支持思考的模型传 `thinking=true` 或反之，行为异常
- **根因**：未按模型能力适配开关
- **修复**：未开思考时显式传 `enable_thinking=false`（`86da0f9`）

### 坑 16 · 常规模型静默能力下降
- **现象**：默认候选模型能力下降影响使用
- **根因**：模型选型不是静态快照
- **修复**：按实际能力调整候选顺序（QwenPlus → Qwen3Max，`af4640f`）
- **教训**：模型候选要持续评估，换模型是常规操作

## 7.5 记忆 / 会话类

### 坑 17 · 摘要窗口每轮滑动都调 LLM
- **现象**：多轮对话每轮都触发一次摘要生成，延迟与成本飙升
- **根因**：摘要触发条件过宽
- **修复**：只在窗口滚动到需要时生成/更新（`807d422`）

### 坑 18 · 消息列表顺序不稳定
- **现象**：并发消息或同秒消息排序抖动
- **根因**：仅按时间排序，缺少稳定决胜键
- **修复**：追加雪花 ID 决胜键保证顺序稳定（`f3e43a9`）

### 坑 19 · 排队请求丢用户上下文
- **现象**：Redis 排队后再执行，请求线程上下文丢失
- **根因**：排队跨线程，ThreadLocal 不传递
- **修复**：保留排队请求的用户上下文（`2fbbb68`，配合 TransmittableThreadLocal）

## 7.6 入库 / 解析类

### 坑 20 · 文件上传防重复摘要栈溢出
- **现象**：上传大文件计算防重复摘要时栈溢出
- **根因**：递归/深层对象遍历
- **修复**：`2c178b4` 修复摘要逻辑

### 坑 21 · Pipeline 重复更新节点唯一键冲突
- **现象**：流水线节点更新时唯一键冲突
- **根因**：建表/更新逻辑与唯一键不一致
- **修复**：`8d314a2`

### 坑 22 · 非法数值条件导致节点误判
- **现象**：节点条件里出现非法数值，被当成可以执行
- **根因**：条件解析未 fail-closed
- **修复**：非法数值条件安全返回 false（`6a1ecf7` / `1c9bfc1`）
- **教训**：解析失败要**默认拒绝**而不是默认放行（fail-closed）

### 坑 23 · 多起点流水线、畸形结构
- **现象**：多起点/畸形条件结构导致执行前失败或不执行
- **根因**：校验不足、分发逻辑没兜底
- **修复**：执行前校验单起点 + 畸形结构 fail-closed（`c9c6ee4` / `dbedd45`）

### 坑 24 · ETag 变化导致跳过远程刷新
- **现象**：远程 URL 文档 ETag 变化时不刷新
- **根因**：ETag 处理逻辑误判"内容未变"
- **修复**：`10def62` 避免 ETag 变化时跳过刷新

### 坑 25 · 卡死文档状态不恢复
- **现象**：文档卡在 RUNNING/FAILED 不重试
- **根因**：调度状态机缺恢复逻辑
- **修复**：`56705f2` 优化卡死文档恢复

### 坑 26 · Excel/表格解析丢合并单元格
- **现象**：Excel 合并单元格、公式、超链接解析丢失
- **根因**：直接用 POI 内建读取，未归一化
- **修复**：`ExcelTableNormalizer`（合并单元格/多行表头/超链接/公式求值）+ `HtmlTableChunker`（colspan/rowspan）

## 7.7 消息队列 / 事务类

### 坑 27 · 事务消息发送失败残留本地回调
- **现象**：事务消息发送失败后，本地事务回调没清理
- **根因**：异常路径未释放注册
- **修复**：`e6342eb` 清理本地事务回调

### 坑 28 · MQ 消费幂等
- **现象**：消息重复投递导致重复入库
- **根因**：RocketMQ 至少一次语义
- **修复**：`IdempotentConsumeAspect`（Redis `SET NX GET` 原子占位，CONSUMING/跳过）

## 7.8 前端 / 基建类

### 坑 29 · Vite 开发服务器绑定 IPv6
- **现象**：开发环境访问 `localhost` 失败或后端连不上
- **根因**：Vite 默认绑定 IPv6 回环
- **修复**：显式绑定 IPv4 回环地址（`444bd16`）

### 坑 30 · MinerU 并发解析打爆 SaaS
- **现象**：大量 PDF 同时解析导致限流/失败
- **根因**：无并发控制
- **修复**：Redisson 分布式信号量控制解析并发（`50afe91`）

## 7.9 排查决策速查（现象 → 先看哪）

| 现象 | 第一时间排查 |
|:---|:---|
| 启动失败报 vector 相关 | PG 是否 pgvector 镜像 / schema 是否手动建 |
| 检索结果怪 | 看"检索归因"日志：各通道召回/存活分布 |
| 模型不回字/卡住 | 首包探测、`ModelHealthStore` 熔断状态 |
| 某模型一直失败 | 是否 HALF_OPEN 名额被占（坑13）|
| 多轮记忆爆/慢 | 摘要触发、`history-keep-turns` |
| 入库没进向量库 | `ChunkSink` 链路、装饰器同步开关、维度校验 |
| 上传的 PDF 没解析 | MIME 探测、ParserRegistry 档位、MinerU 信号量 |
| 图谱检索异常 | `rag.graph.type` 与通道开关、超时配置 |

## 7.10 心态总结

踩坑最多的不是"写不出来"，而是**默认假设**：分数一定合法、缓存一定兼容、镜像一定带扩展、跨线程上下文一定还在、远端一定在超时内响应。这份项目几乎所有"工程味"都来自对这些假设的逐个击破——这也是它值得写进简历的原因。
