# 3 · 程序文件详解

> 逐个讲清楚每个核心类**是什么、在流程中扮演什么角色、关键字段/方法、和谁协作**。按"数据流"编排：先入口与约定，再到 RAG 大脑的各零件，然后是检索、模型层、入库、公共底座与 MCP。建议配合 [4-项目完整流程] 一起读。

## 3.1 入口与统一约定（framework/convention）

### `AskoraApplication`（主启动类）
`bootstrap/.../AskoraApplication.java`
- 标注 `@SpringBootApplication`、`@EnableScheduling`、`@EnableLogRecord(tenant="askora", proxyTargetClass=true)`（bizlog 审计）、`@MapperScan`（扫描五个业务模块的 Mapper）
- 三个特性共同拉开应用：定时任务（URL 远程刷新）、操作审计、MyBatis-Plus Mapper

### `Result<T>`（统一响应体）
`framework/.../convention/Result.java`
- `code`（`"0"` = 成功，等价 `success=true`）/ `message` / `data` / `requestId`
- 全后端统一返回外壳，前端靠 `code` 判成败
- `Results` 工厂类生产成功/失败结果

### `ChatMessage / ChatRequest`（LLM 对话统一模型）
`framework/.../convention/ChatMessage.java` · `ChatRequest.java`
- `ChatMessage`：一个对话轮次，`Role`(SYSTEM/USER/ASSISTANT) + `MessageStatus`(NORMAL/INTERRUPTED/REJECTED)，assistant 专属字段：`thinkingContent`、`thinkingDuration`、`sources`、`retrievedChunks`、`replyToMessageId`
- `ChatRequest`：统一采样参数（`temperature/topP/topK/maxTokens`、`thinking`、`enableTools`）。**各供应商差异被这两类对象吸收**，上层只管业务
- 工厂方法 `ChatMessage.system()/user()/assistant()`

### `RetrievedChunk / RetrievedChunkKey`（检索命中块）
`framework/.../convention/RetrievedChunk.java` · `RetrievedChunkKey.java`
- `RetrievedChunk`：一次命中，`id/text/score/collectionName/docId/chunkIndex/docName`；静态 `BY_SCORE_DESC` 比较器把 null/NaN/∞ 归到 -inf 沉底（**防脏分数**）
- `RetrievedChunkKey`：去重键——有 id 用 id，否则 **SHA-256 文本哈希**（联网无 id 的块也能统一去重）

### `SourceRef / GroundingChunk`
- `SourceRef`：**文档级引用**（index/docId/docName/sourceType/url/excerpt），用于前端来源面板与行内角标
- `GroundingChunk`：**原文支撑片段**（更长、含 docName+text），用于"推荐追问"的 grounding，与 SourceRef 职责刻意分开

## 3.2 上下文与公共底座（framework）

### `UserContext`（用户线程上下文）
`framework/.../context/UserContext.java`
- 基于 **TransmittableThreadLocal**，存 `LoginUser`（userId/username/role/avatar）
- 静态 `getUserId()/requireUser()/set()/clear()`；由 `user/config/UserContextInterceptor`（bootstrap）在请求进 sa-token 校验后填充
- **为什么 TTL**：RAG 大量 `CompletableFuture`/线程池，普通 ThreadLocal 跨线程即丢

### `RagTraceContext + RagTraceNode`（链路追踪）
`framework/.../trace/`
- `RagTraceContext`：TTL 保存 `traceId/taskId` + 一个节点栈（push/pop/current）；跨异步边界的深度追踪靠它
- `RagTraceNode`：`@interface`，标在检索/意图等方法上（如 `@RagTraceNode(name="retrieval-engine", type="RETRIEVE")`），切面负责记录每节点耗时与结果
- 运行态实现在 bootstrap `rag/trace/`（`RagStreamTraceSupportImpl`、`StreamChatTraceRunner`）

### 异常体系
`framework/.../exception/` + `errorcode/`
- `IErrorCode` 接口，`BaseErrorCode` 枚举（阿里规范式码位：`A000001` 客户端错、`A00xxxx` 细分、`B000001` 服务端、`C000001` 远程）
- `AbstractException` → `ClientException`(4xx) / `ServiceException` / `RemoteException`(第三方)
- `web/GlobalExceptionHandler`：统一把各类异常（参数校验/sa-token/超大上传/兜底 Throwable）映射成 `Result`

### 分布式 ID
`framework/.../id/`
- `CustomIdentifierGenerator implements MyBatis-Plus IdentifierGenerator`：返回 hutool 雪花
- `SnowflakeIdInitializer`：`@PostConstruct` 跑 Redis Lua `snowflake_init.lua` **原子分配 workerId/dataCenterId**，多实例不撞

### 幂等
`framework/.../idempotent/`
- `IdempotentConsumeAspect`：MQ 消费幂等（Redis `SET NX GET PX` 原子占位，CONSUMING→延迟重试/跳过）
- `IdempotentSubmitAspect`：请求幂等（Redisson `RLock`，key=路径:用户:argsMD5）

### 消息队列封装
`framework/.../mq/`
- `MessageWrapper` 信封（keys/body/uuid/timestamp）
- `MessageQueueProducer` 接口 → `RocketMQProducerAdapter`（`send` / `sendInTransaction`）
- `DelegatingTransactionListener`：把 RocketMQ 事务监听和具体业务解耦，业务注册"本地事务 + `TransactionChecker`"

## 3.3 模型层（infra-ai）——能力供给

### `ChatClient` + 各供应商实现
`infra/chat/`
- `ChatClient` 接口：统一流式/非流式聊天契约
- 实现：`BaiLianChatClient`(百炼) / `SiliconFlowChatClient`(硅基) / `AIHubMixChatClient` / `OllamaChatClient`
- `AbstractOpenAIStyleChatClient`：抽象公共"OpenAI 兼容协议"的 SSE 解析、HTTP 拼接（**消除重复**）
- `OpenAIStyleSseParser`：解析 SSE 流增量

### `LLMService + RoutingLLMService`（调用入口）
`infra/chat/LLMService.java` · `RoutingLLMService.java`
- `LLMService`：业务层唯一调用的聊天门面（`streamChat(req, callback)` 返回 `StreamCancellationHandle`）
- `RoutingLLMService`：按档位选候选、交给 `ModelRoutingExecutor` 故障转移；负责整体降级策略

### `ModelRoutingExecutor`（路由/故障转移）
`infra/model/ModelRoutingExecutor.java`
- 签名 `executeWithFallback(capability, targets, clientResolver, caller)`
- 按候选优先级逐个尝试：`allowCall` 熔断门控 → 成功 `markSuccess` 返回；失败 `markFailure` 降级下一个；全败抛 `RemoteException`
- `capability` 区分 CHAT/EMBEDDING/RERANK 各自的候选池

### `ModelHealthStore`（三态熔断）
`infra/model/ModelHealthStore.java`
- 每 targetId 一个 `ModelHealth`，`ConcurrentHashMap` 存储、`compute` 做原子迁移
- 状态机：CLOSED（正常）→ 连续失败达阈值 OPEN（冷却）→ 冷却后首个请求 HALF_OPEN 探活 → 成功 CLOSED / 失败回 OPEN
- `allowCall` 返回 `CallPermit`（可带半开 token），`markSuccess/markFailure/releaseHalfOpenPermit` 驱动转移
- **半开互斥**（`halfOpenInFlight`）防止探活被并发冲垮

### `LlmFirstPacketProbe + ProbeStreamBridge`
`infra/chat/`
- 首包探测：流式响应"第一个 token"到达前的老化检测，超时算失败并可提前降级
- `ProbeStreamBridge`：把探测包装在回调流上；中断时由**持有者**释放半开名额（修复 #75）

### Embedding / Rerank / VLM / token
- `EmbeddingService + RoutingEmbeddingService`：向量化，多候选路由
- `RerankService + RoutingRerankService`：重排（`BaiLianRerankClient`/`NoopRerankClient`）
- `VlmService + RoutingVlmService`：图生文（图片解析用）
- `HeuristicTokenCounterService`：启发式算 token（控上下文成本）

## 3.4 RAG 大脑编排（bootstrap/rag）

### `RAGChatController`（SSE 入口）
`rag/controller/RAGChatController.java`
- 暴露 `POST /rag/chat/stream`，接收 `SseEmitter`，转给 `RAGChatService.streamChat`

### `RAGChatServiceImpl`（对话服务）
`rag/service/impl/RAGChatServiceImpl.java`
- 关键动作：雪花 ID 兜底会话/任务 ID → `callbackFactory.createChatEventHandler` 建 SSE 回调 → `chatQueueLimiter.enqueue`（排队限流）→ `traceRunner.run`（Trace 包裹）→ 构建 `StreamChatContext` → `chatPipeline.execute`
- 支持 `stopTask(taskId)` 跨实例取消

### `StreamChatPipeline`（**全项目最重要的一条流水线**）
`rag/service/pipeline/StreamChatPipeline.java`
- 七个私有阶段方法按序调用，方法名即阶段名：
  `loadMemory → rewriteQuery → resolveIntents → handleGuidance(短路) → handleSystemOnly(短路) → retrieve → handleEmptyRetrieval(短路) → streamRagResponse`
- 每个 `handleXxx` 返回 true 表示**已处理并短路**，避免多分支炸毛
- 依赖全注入：memoryService / queryRewriteService / intentResolver / guidanceService / retrievalEngine / llmService / promptBuilder / agentPromptResolver / taskManager / sourcesAssembler / groundingChunksAssembler / citationContextEnricher

### `StreamChatContext`（流水线上下文载体）
`rag/service/pipeline/StreamChatContext.java`
- Lombok `@Builder`，承载 question/conversationId/taskId/deepThinking/userId/callback + 各阶段中间产物（history/rewriteResult/subIntents 等）

### `StreamChatEventHandler`（SSE 回调实现，高频）
`rag/service/handler/StreamChatEventHandler.java`
- 把 `StreamCallback` 增量翻译成 SSE 事件序列：
  - `meta`（conversationId/taskId）→ `message`（think/response，按 `messageChunkSize` 按**码点**切块推送，避免切坏 emoji/中文）→ `finish`（来源/标题）→ `done`
- 承担"回答落库"：`onComplete` 把完整回答（含思考/来源/grounding）持久化为一条 assistant 消息再收尾
- 取消兜底：`buildCompletionPayloadOnCancel` 把已累积内容以 `INTERRUPTED` 状态先落库，不丢内容
- 每个回调入口先查 `taskManager.isCancelled`

### `StreamTaskManager`
`rag/service/handler/StreamTaskManager.java`
- 登记/取消流式任务，供 **SSE 连接跨实例取消**（Redis 协同）；`bindHandle` 绑 LLM 的取消句柄

### `ChatQueueLimiter + FairDistributedRateLimiter`
`rag/service/ratelimit/`
- `ChatQueueLimiter`：入队（Redis 公平队列）→ 领取 → 执行 → 释放
- `FairDistributedRateLimiter`：分布式并发计数（`max-concurrent=10`、`max-wait-seconds=15`），保证突发请求不压垮模型服务

## 3.5 问题理解（rewrite / intent / guidance）

### `QueryRewriteService + MultiQuestionRewriteService`
`rag/core/rewrite/`
- 接口：`rewrite()`（改写）、`rewriteWithSplit(question, history)`（改写+多问句拆分）
- 用 LLM 一次返回"改写句 + 子问题列表"；失败回退原问题
- `QueryTermMappingService/...CacheManager/...Util`：查询术语映射（把用户口语映射到规范术语），带缓存

### `IntentResolver`（意图解析器）
`rag/core/intent/IntentResolver.java`
- `resolve(rewriteResult)`：对每个子问题并行分类（专用 `intentClassifyExecutor`），失败降级空意图，最后 `capTotalIntents` 限额
- `mergeIntentGroup`：把子问题意图按 KB/MCP 两通道合并
- `isSystemOnly`：是否只命中单一系统闲聊意图
- `capTotalIntents`：每个子问题保底 1 个最高分意图 + 剩余按分补

### `IntentClassifier`（意图分类器）
`rag/core/intent/IntentClassifier.java`
- 接口，支持两种实现策略：**串行分类**（一次性 LLM 识别全部意图，节点少）/ **并行分类**（按 Domain 拆开并行 LLM，节点多）
- `classifyTargets(question)` 返回按分降序的 `List<NodeScore>`

### `IntentNode / IntentNodeRegistry / NodeScore`
`rag/core/intent/`
- `IntentNode`：意图树节点，含 `level`(DOMAIN/CATEGORY/...) / `kind`(KB/SYSTEM/MCP) / `promptTemplate` / `topK` / `paramPromptTemplate` / `collectionNames` / `mcptoolId`
- `IntentNodeRegistry`：节点注册表（含父链查询，歧义判定要沿父链找系统级/域级）
- `NodeScore`：节点 + LLM 打分
- 意图树数据在 `t_intent_node` 表，管理端 `IntentTreeController` 维护

### `IntentGuidanceService`（歧义澄清）
`rag/core/guidance/IntentGuidanceService.java`
- 规则层：`score ratio` 快速判断（明确/点名系统则跳过）
- LLM 层：`AmbiguityLLMChecker.checkAmbiguity` 边界区间语义确认
- 输出 `GuidanceDecision`，命中则渲染带编号选项的 `guidance-prompt.st` 模板

## 3.6 检索层（retrieval）

### `RetrievalEngine`（检索总调度）
`rag/core/retrieval/RetrievalEngine.java`
- 一次算好 `RetrievalBudget`（recall-budget / candidate-limit / context-topK 三段，单调收窄）
- 对每个子问题并行 `buildSubQuestionContext`（`ragContextExecutor`），失败降级空上下文
- 单/多子问题分别拼 KB/MCP 上下文（多子问题用 `sub-question-kb-wrapper` 分段）
- MCP 意图走 `McpToolExecutor` 工具调用（参数提取三态：SUCCESS 调用 / NEED_CLARIFICATION 注入追问提示 / FAILED 注入失败提示）

### `MultiChannelRetrievalEngine`
`rag/core/retrieval/MultiChannelRetrievalEngine.java`
- 并行执行启用通道（`ragRetrievalExecutor`），**通道级超时**（`orTimeout`）降级空结果
- 按 `order` 依序跑后置处理器链（去重→融合→Rerank），单处理器异常跳过
- `deriveAttribution`：按"库→意图"绑定关系给 Chunk 推导意图归属

### `SearchChannel` 及其实现（四通道）
`rag/core/retrieval/channel/`
- `VectorSearchChannel`：向量。**定向/全局合一**（避免同一证据在 RRF 自我加权），定向时并补"未命中库"补充路（`supplementRatio`），用 `CollectionParallelRetriever` 逐库并行 fan-out 兜底
- `KeywordSearchChannel`：ES BM25 关键词
- `GraphSearchChannel`：LightRAG 图谱
- `WebSearchChannel`：You.com 联网
- `RetrievalScopeResolver`：判定定向/全局（仅看 KB 意图最高分，confidence-threshold=0.6）

### 后置处理器链
`rag/core/retrieval/postprocessor/`
- `DeduplicationPostProcessor`(order 1)：按 `RetrievedChunkKey` 去重
- `FusionPostProcessor`(order 5)：RRF 融合 + 按 `rerank-candidate-limit` 截断；输出"检索归因"日志（按通道分布）
- `MetadataEnrichmentPostProcessor`：补齐文档元数据
- `RerankPostProcessor`(order 10)：交叉注意力精排到 `contextTopK`；重点打"图谱证据存活率"日志

## 3.7 会话记忆 / Prompt / 来源

### `ConversationMemoryService`
`rag/core/memory/ConversationMemoryService.java`
- `load(conversationId, userId)`：返回历史（摘要 + N 轮消息）

## 3.8 知识生产（core + knowledge + ingestion）

### `DefaultIngestionKernel`（入库内核）
`core/ingest/DefaultIngestionKernel.java`
- 固定五阶段：`identity → parse → chunk → embed → index`，每段计时写 `IngestionOutcome.Timings`
- 全链路**单事务**写入（`TransactionOperations`），分片落库
- 被 `KnowledgeDocumentServiceImpl.runChunkTask` 直接调用（v1 主路径）

### 解析器（core/parser）
- `MimeTypeDetector`：Tika 探测 MIME（唯一权威）
- `ParserRegistry`：MIME × 档位(FAST/FIDELITY) 二维表，**启动自检**每个扩展名都有 FAST 解析器
- `TikaDocumentParser` / `MarkdownDocumentParser`(commonmark+GFM) / `CsvDocumentParser` / `ExcelDocumentParser`(POI+表格归一化) / `MinerUDocumentParser`(SaaS+Redisson 信号量) / `ImageDocumentParser`(VLM+Batik)

### 分块器（core/chunk）
- `ChunkingService` → `BlockAwareChunkerDispatcher`（按 Block 类型选 Chunker）
- `HeadingChunker/CodeChunker/TableChunker/HtmlTableChunker/ImageChunker/ParagraphChunker/ListChunker`
- `HeadingHandler` 维护章节路径；`ChunkPacker` 按标题章节级打包（`min unit = maxChars/4`）
- `TextSplitter`：边界感知切分（换行/CJK 句末/英文句末，URL 修复）

### 知识库领域（knowledge）
- `KnowledgeBaseDO（t_knowledge_base）`：name/embeddingModel/collectionName
- `KnowledgeDocumentDO`：docName/status(PENDING..FAILED)/processMode(CHUNK/PIPELINE)/ingestionSpec(JSONB)
- `KnowledgeChunkDO`：content/contentHash(Hash256)/tokenCount/embeddingText
- `KnowledgeBaseServiceImpl`：创建(校验唯一/建存储/ensureVectorSpace)、删除（RocketMQ 事务消息异步清理底层）、改 embeddingModel 限制
- `KnowledgeDocumentServiceImpl`：上传、startChunk（事务消息）、enable/disable（重嵌/删向量）、远程刷新
- `RelationalChunkSink + VectorChunkSink`（sink 扇出，单事务）

### 流水线引擎（ingestion，v2，重构中）
- `IngestionEngine`：校验（单起点/无环）→ 沿 `nextNodeId` 同步走节点链，`nodeType→IngestionNode` 注册表分派
- 节点类型：`fetcher/parser/enhancer/chunker/enricher/indexer`
- 当前 `ProcessMode.PIPELINE` 分支被注释为"管道模式重构中，暂不可用"（直接 chunk 是主路径）

## 3.12 关键配置类（一个都不能少理解）
