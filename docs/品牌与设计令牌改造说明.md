# 品牌收口 + 设计令牌系统 + 暗色模式

## 这个 PR 做了什么

三块互相依赖的工作，按依赖顺序：

1. **品牌收口** —— 全仓旧标识（Ragent / nageoffer / moacode）清零；品牌标识收敛为唯一组件
2. **设计令牌系统** —— 把散落在 TSX 与 CSS 里的 800+ 处硬编码颜色收敛到语义令牌，并补齐明暗两套值
3. **暗色模式打通** —— 从"有开关无样式"变成可用（此前 `.dark` 是空壳）

## 1. 品牌

**问题**：同一个品牌有 4 种画法、3 种概念 —— 聊天页是「?」+ 圆环的矢量图，登录页是 lucide `Sparkles`，后台侧栏是 lucide `Bot`，favicon 用 `<text font-family="Arial">?</text>` 画。同一份矢量 path 被内联复制了 4 遍。

**做法**：
- 新建 `components/brand/AskoraLogo.tsx` 作为**唯一定义处**，导出 `ASKORA_MARK_D` 与 `askoraMarkSvgBody()`，让 React 组件与静态 SVG 共用同一份几何
- 标记为纯 path 描边，**零字体依赖**（早先 favicon 跨平台不一致的根源就是字体依赖）
- 提供 `mark` / `plain` / `wordmark` 三个变体，`plain` 走 `currentColor` 供彩色底与单色印刷使用
- 静态资源同步：`favicon.svg` · `askora-logo.svg` · `askora-avatar.svg` · `.idea/icon.svg` · `site.webmanifest`
- 旧标识全仓清零（含文档、`resources/docker`、`resources/database`、`frontend/TESTING.md` 里泄露的原作者本地路径）

## 2. 设计令牌系统

**问题**：项目里本就定义了完整刻度（字号 / 间距 / 圆角），但**引用数全是 0**；页面里是手写值 —— 字号一项就有 45 处、8 个不同值（`10 · 11 · 12 · 12.5 · 13 · 13.5 · 14 · 15px`）。其中 `12.5` 与 `13.5` 是决定性证据：任何刻度都产不出这两个值。

另外 `globals.css` 里同时存在三套变量：HSL 契约变量（tailwind 消费）、「新设计系统」语义令牌、以及一块标注"兼容性保留"的旧变量。

**做法**：
- 删除旧变量块（11 个，逐个核实零引用后）
- 建立并补齐语义令牌：中性 / 品牌强调 / 紫色辅助 / 状态色（每状态 7 档 soft→text-deep）/ 危险操作 / 品牌标识
- **硬编码颜色收敛 800+ 处**，覆盖三层不同写法：
  - TSX 里的 hex 与 Tailwind 调色板类
  - `globals.css` 里 `@apply` 的调色板类
  - `globals.css` 里 `@apply bg-white` 这类**具名色**（它落在"字面量"和"调色板类"两批的缝里）
- 字号收敛到已有刻度，消除半像素值
- **有意保留的**（不该令牌化）：图谱节点分类色板（AntV category10）、图表色板、图片预览的代码色板、蒙层 scrim（两种主题下都该是深色）

## 3. 暗色模式

**问题**：`.dark` 块只有 `color-scheme: light;`（声明自己是浅色，等于空壳），`toggleTheme` 无任何 UI 调用 —— 有开关、有状态、有持久化，就是没按钮也没样式。

**做法**：
- 补全 `.dark` 令牌：整组 HSL 契约变量 + 语义令牌（**不覆盖**尺寸类令牌 —— 与主题无关，重复定义只会造出两份事实）
- 接上切换按钮（`Header` 与后台顶栏）
- 补两处此前完全缺失的覆盖：`--trace-*` / `--kpi-*` 作用域令牌（它们挂在 `.admin-layout` 下、只有浅色值）
- 强调色令牌补暗色值（`text-indigo-600` 等都映射到了它们，原值在近黑底上对比不足）

## 验证方式（重要）

本 PR 的多数改动遵循一条硬约束：**新令牌的 `:root` 值与被替换的原子面量逐字节相同**，因此**浅色模式的渲染结果可证明不变**。每个批次都做了逐令牌核对。

```
tsc          24 errors —— 全部为既存，且都在本次未改动的 4 个文件
             (KnowledgeDocumentsPage / chatStore / FeedbackButtons / IngestionPage)
vite build   ✅ 通过
```

**已知未验证**：页面的实际观感。本次改动涉及 800+ 处颜色与若干尺寸，构建与令牌取值可证明正确，**视觉呈现需人工逐页核对**（明暗各一轮）。

## 已知限制 / 未做的部分

- **`globals.css` 未能拆分**：Tailwind v3 只在含 `@tailwind components` 指令的文件里保留 `@layer components` 内容，而 Vite 对每个 CSS 文件分别跑 PostCSS —— 把该层搬到别的文件会整块丢弃（实测 `.admin-layout` 命中数 502 → 0）。三种方案均已实测，`@import` 提前会翻转层叠顺序。**需要先改构建流水线**。详见 `docs/CHANGELOG.md`。
- **图谱画布与 G6 tooltip 的暗色缺口**：它们是 JS 内联样式与画布配置，令牌化触及不到，需在 JS 侧读主题。
- **antd 分类色板**：`KnowledgeGraphPage` 的节点类型色板有意保留，未拉平。
